# CityMETER Shopping Centers & Retail Venues — owner preferences

Recorded 2026-10-25 (release 0.1.0, data refreshed from the 15:06 export). Read `PRODUCT_STATEMENT.md` (0.5) and `DATA_METHOD.md` before changing what the page counts or argues.

- **Design system:** LDS 0.9.7 (`v0.9.7-owner.1`, `standalone-0.9.7-r1`, `color-srgb-10`, SHA-256 `d3085cbc…d432d96`). Colours come only from `assets/theme.css` and `js/scales.js`; never approximate a value by eye. Analytical scales use **all 41 samples** of the exact LDS LUTs (owner decision D8, 2026-10-25 — “scale สีให้ใช้ 41 สี ตาม LDS ทั้งหมด”): `buildRamp()` gives each value the LUT sample of its rank (lowest 0, highest 40, ties share, nothing interpolated) for district fills, province fills and the matrix, and `rampLegendHTML()` draws all 41 samples with value ticks; never a 3/5-class pick, a mixed colour or a per-theme value. Numbers on samples where neither ink reaches 4.5:1 sit on a neutral plate. Categorical groups use `landometer-series-10-v8` with a shape cue per group; no purple or brown, and series 2–3 stay unused because they collide with the orange density scale. No decorative brackets or coloured left rails; keyboard focus always visible.
- **Same look and behaviour as Luxury Brands** (`montri-th/luxurybrands`, 0.5): map-first CityMETER layout, 3D first paint, focus + quiet context, paper basemap from `js/map-style.js`, venue x-ray, camera presets (`city`, `model`, `eye` at venue level only, `plan` when 3D is off; every 3D preset at pitch ≤ 90° − fov/2 − 3°), breadcrumb with production codes. Do not reorder the host-building, massing and x-ray layers casually (see Luxury `AGENTS.md`).
- **Counting is the product (owner retail-venue definition 2026-10-23):** count only qualified, countable venues; supply excludes future projects and closed-by-evidence; parents never add their components; a qualified component whose parent is not qualified counts as its own venue only when it is a shopping centre or mall (owner decision D6, 2026-10-25: `ORPHAN_COUNTED_GROUPS`, `OWNER_SHOPPING_CENTRES`) and never when it is a possible duplicate; category rules the owner accepted and recorded in the registry (`owner_<rule>_definition_accepted_*`, `owner_confirmed_*`; decision D7) count as qualified with tier `owner`, and the venue panel always says so (“ผ่านนิยามตามกฎที่เจ้าของข้อมูลยอมรับ · <rule>”) — never as source evidence; records still awaiting review and records whose review closed unconfirmed (`reviewed_*_unconfirmed`, state `reviewed`) are quiet grey context labelled by state (zoom ≥ 11, hideable, searchable, outside the tab order) and never enter a number; negative determinations are not shown. Unknown `venue_qualification_status` values must be classified in `qualification_rule()`, and unknown `count_role` values of qualified rows in `COUNTED_ROLES` / `COMPONENT_ROLES` / `HELD_ROLES`, before publishing — the test suite fails until they are. A status that holds the count as a possible duplicate wins over a counted role.
- **Aha first (D1):** the first view frames the three districts with the highest venues/km² in the province of the densest district and states the share, numerator, denominator and area context, computed from the data every time (`js/area-insight.js`). No onboarding gate; no caveat banner on the first view. Snapshot numbers in docs are fixtures, not UI constants.
- **Areas are official boundaries:** membership is precomputed point-in-polygon on full-resolution OpenGISData-Thailand districts (`provinceCode`, `districtCode`); never assign by name or nearest area; district and province ids are CityMETER production codes.
- **Size (D3):** legacy GLA/GFA estimates appear only in the venue panel with their method; never in filters, charts, tables, totals or rankings. The dataset name is “ศูนย์การค้าและสถานที่ค้าปลีก: จำนวน ประเภท และผู้บริหาร” (D2).
- **Evidence per field:** every value in the venue panel carries its basis, public source link and check date when available; missing is “ยังไม่มีข้อมูล”, never 0; conflicts keep both sides. Operator charts say “สัดส่วนจำนวนสถานที่”, never market share.
- **Public files carry no private links:** no `docs.google.com` / `drive.google.com` URLs and no Drive/Sheets file ids anywhere in the repository (a test scans every text file). Research Master and Dataset Registry are internal working references; the pitch documents and team statement stay internal.
- **Scale:** the registry may grow to thousands of qualified venues. Keep all venues on GPU layers, DOM pins only for the focus (≤ 600), logos ≤ 250 at zoom ≥ 14 inside the focus, detail shards sized by `shard_count()`, and the table paginated.
- **Data refresh:** `npm run data:refresh -- <csv-export-dir> <geometry-bundle-dir> [<logo-dirs>]`, then read `data/build-report.json`. Logos are used only when their bytes match the sheet SHA-256; lookup by `venue_id` only; collecting files is not a trademark licence. When logo files arrive through a Drive connector as base64 text, never retype the text (long repeated runs drift): save the tool result with a script and keep only files whose SHA-256 equals the sheet.
- **Copy:** short, natural Thai: สถานที่ · ศูนย์การค้า · คอมมูนิตี้มอลล์ · ตลาด · สถานีบริการ · ผู้บริหาร · แห่ง · เขต/อำเภอ · ยังไม่ผ่านนิยาม. Units, provenance and limits live in the data line, help and docs. No “ทำเลทอง” or “ช่องว่างตลาด” claims.
- **Release:** review actual Thai and English at 390 px and desktop in light and dark before calling a change done. Bump the `?v=` tag on the entry scripts and stylesheets in `index.html`, then run `python3 scripts/build-static.py` — its import map gives every module in `js/` the same tag, so browsers never mix cached older modules with a new release. Local renders are not proof of a live release: push, wait for Pages, run `npm run handoff:manifest` and `npm run verify:live`, and check the live page in a real browser.
