# CityMETER: ศูนย์การค้าและสถานที่ค้าปลีก

**Live demo: [montri-th.github.io/shoppingcenter](https://montri-th.github.io/shoppingcenter/)** · [Source repository](https://github.com/montri-th/shoppingcenter) · [Product statement](PRODUCT_STATEMENT.md) · [วิธีจัดทำข้อมูล](DATA_METHOD.md)

ย่านนี้มีพื้นที่ค้าปลีกแบบไหนอยู่แล้ว ของใคร มีร้านอะไรอยู่ข้างใน และอะไรกำลังจะเปิด: แผนที่เมือง 3 มิติของศูนย์การค้าและสถานที่ค้าปลีกในไทย ที่นับเฉพาะสถานที่ที่ผ่านนิยาม แยกประเภทก่อนเทียบ และเปิดดูที่มาได้ทุกช่อง หน้าตาและพฤติกรรมเดียวกับ [CityMETER: Luxury Brands](https://montri-th.github.io/luxurybrands/) แต่หน่วยของข้อมูลคือ **สถานที่ค้าปลีก** และหน่วยพื้นที่คือ **เขต/อำเภอตามขอบเขตทางการ**

**Research snapshot: ข้อมูลตรวจถึง 25 ต.ค. 2569 · Grain: หนึ่งสถานที่ (site / parent complex / retail component แยกแถว) · สถานะ: public research demo ไม่ใช่ production release**

## ใช้งาน

```sh
npm start        # http://127.0.0.1:4173/
npm test         # Node ≥ 20
```

ไม่มี build step และไม่มี framework: HTML/CSS + ES modules ไลบรารีภายนอกตัวเดียวคือ MapLibre GL 5.6.2 (pin ไว้ใน `js/vendors.js`) basemap และมวลอาคารจาก [OpenFreeMap](https://openfreemap.org/) (OpenMapTiles schema, ข้อมูล OpenStreetMap) กราฟวาดเองด้วย HTML/SVG ชุดทดสอบ 75 ข้อตรวจสัญญาข้อมูล (ตัวเลขตรงกับ meta, รหัสจังหวัด/เขตตรง production, ไม่มีลิงก์หรือรหัสไฟล์ภายใน, ทุกสถานะและบทบาทการนับถูกจัดกฎ), การนับ, ข้อค้นพบแรก, สเกลสี LDS 41 ระดับ, แผงข้อมูล, โลโก้, หมุด, อาคาร, breadcrumb และ import map ของ cache tag ส่วนหน้าจอจริงตรวจในเบราว์เซอร์แยกต่างหาก ([handoff/VERIFICATION.md](handoff/VERIFICATION.md))

## สิ่งที่สำรวจได้

- **3D ก่อน เขตก่อน:** หน้าแรกเป็นเมือง 3 มิติที่โฟกัส 3 เขตที่มีสถานที่ต่อ ตร.กม. สูงสุดของจังหวัดที่มีเขตหนาแน่นที่สุด พร้อมข้อค้นพบแรก ตัวตั้ง ตัวหาร และบริบทพื้นที่ คำสั่งถัดไป: ดูทุกเขต (`?areas=all`) · ทั้งประเทศ · เทียบพื้นที่
- **นับเฉพาะที่ผ่านนิยาม:** ผ่านด้วยหลักฐาน หรือด้วยกฎรายประเภทที่เจ้าของข้อมูลยอมรับ (Owner-stated: ตลาด สถานีบริการน้ำมันที่มีร้านค้า และอื่น ๆ — แผงสถานที่บอกว่าผ่านทางใด) · โครงการแม่ไม่บวกกับพื้นที่ย่อย · พื้นที่ค้าปลีกที่เป็นศูนย์การค้าแต่โครงการแม่ยังไม่ผ่านนิยามนับเป็นสถานที่ของตัวเอง (D6) · รายการที่อาจซ้ำหรือการนับแยกยังรอตรวจไม่นับ · โครงการที่กำลังมาและที่ปิดตามหลักฐานแยกไว้ · รายการที่ยังไม่ผ่านนิยาม (รอตรวจ หรือตรวจแล้วยังยืนยันไม่ได้) เป็นจุดเทาเงียบที่ zoom ≥ 11 ไม่อยู่ใน tab order ซ่อนได้ (`?pending=0`)
- **8 กลุ่มประเภทพร้อมรูปทรงกำกับ:** ศูนย์การค้า · คอมมูนิตี้มอลล์ · ตลาด · ไฮเปอร์มาร์เก็ตและซูเปอร์มาร์เก็ตที่มีร้านเช่า · พื้นที่ค้าปลีกในโครงการ · เอาท์เล็ต · สถานีบริการน้ำมันและจุดพักรถ · อื่น ๆ (สี `landometer-series-10-v8` + รูปทรง ไม่พึ่งสีอย่างเดียว)
- **พื้นที่:** ทั้งประเทศ = กรอบจังหวัดระบายจำนวนสถานที่ (LDS `count`) · จังหวัด = เขต/อำเภอระบายสถานที่ต่อ ตร.กม. (LDS `density.area`) · ใช้ครบ 41 สีของ LUT ตามลำดับค่าของพื้นที่ที่อ่าน (คำสั่งเจ้าของ 25 ต.ค. 2569) คำอธิบายแผนที่แสดงทั้ง 41 สีพร้อมค่าที่ตำแหน่งของมัน · ศูนย์ที่วัดได้มีเส้นขอบศูนย์ แยกจากไม่มีข้อมูล · HEX เดียวกันทั้งสองธีม
- **สถานที่:** หลักฐานรายช่อง (ชื่อ ประเภท การผ่านนิยาม สถานะ ผู้บริหาร เว็บทางการ เวลาเปิดและขอบเขตของเวลา ปีที่เปิด ที่ตั้งและบทบาทพิกัด) · ขนาดแบบค่าประมาณเดิมแสดงเฉพาะที่นี่พร้อมวิธีคำนวณ ไม่รวม ไม่จัดอันดับ (D3) · ร้านที่ยืนยันว่าอยู่ข้างในพร้อมลิงก์ไป Luxury Brands เมื่อเปิดสถานที่เดียวกันได้ · พื้นที่ย่อยและโครงการแม่ · รหัส `venue_id` / Shopping Center id / CityMETER id
- **อาคาร:** อาคารของสถานที่ที่มีรูปทรงผ่านเกณฑ์เป็นสีน้ำเงิน มองเห็นและกดได้เสมอ (venue x-ray) · ความสูงที่ไม่รู้ใช้แผ่นแสดงผล 3 ม. และไม่ถูกอ้างเป็นข้อเท็จจริง · มุมสถาปนิกที่ระดับสถานที่
- **breadcrumb:** ประเทศไทย › จังหวัด › เขต/อำเภอ › สถานที่ ด้วยรหัสของ CityMETER production (`?province=BKK&district=1007&venue=<venue_id>`)
- **กราฟและตาราง:** เขตหนาแน่น · ประเภทในแต่ละพื้นที่ (ช่องเท่ากัน) · ผู้บริหาร (สัดส่วนจำนวนสถานที่ ไม่ใช่ market share) · ตารางสถานที่ทีละ 25 แถว
- **ค้นหา:** ชื่อไทย/อังกฤษ ชื่อเรียกอื่น ผู้บริหาร และรหัส (substring หลัง normalize ไม่ fuzzy) รายการที่ยังไม่ผ่านนิยามติดป้ายสถานะและว่าไม่นับ
- ไม่มีลิงก์เอกสารภายในในหน้าเว็บหรือไฟล์ข้อมูล · missing ไม่แสดงเป็น 0 · ไม่มี caveat บนหน้าแรก ขอบเขตและข้อจำกัดอยู่ในส่วนข้อมูล วิธีใช้ และเอกสาร

## อัปเดตข้อมูล

ทะเบียนชุดนี้กำลังปิดรายการรอตรวจนิยาม (เจ้าของคาดว่าจะผ่านนิยามมากกว่า 7,000 จุด — Owner-stated 25 ต.ค. 2569 ยังไม่ใช่ข้อเท็จจริงของข้อมูล; snapshot นี้ผ่านนิยาม 6,045) เว็บรองรับขนาดนั้นโดยไม่ต้องแก้โค้ด: จุดทั้งหมดวาดด้วย GPU layer, หมุด DOM เฉพาะส่วนที่โฟกัส (≤ 600 ไม่เช่นนั้นเป็นสัญลักษณ์ GPU), รายละเอียดสถานที่แยกเป็น shard ที่เพิ่มจำนวนเองตามขนาดทะเบียน และตัวเลข ข้อค้นพบแรก สเกลสี และตารางสรุปคำนวณใหม่จากข้อมูลทุกครั้ง

1. Export แท็บของ Research Master เป็น CSV ลงโฟลเดอร์เดียว: `01_VENUES`, `09_RELATIONSHIPS`, `10_VENUE_LOGOS` และ `13_BUILDING_LINKS` (ชื่อไฟล์ลงท้ายด้วย `<แท็บ>.csv`) พร้อมโฟลเดอร์ geometry bundle ที่แตก zip แล้ว และโฟลเดอร์ไฟล์โลโก้ใหม่ (ถ้ามี)
2. รันคำสั่งเดียว:
   ```sh
   npm run data:refresh -- <csv-export-dir> <geometry-bundle-dir> [<logo-files-dir> ...]
   ```
   สคริปต์ดึงขอบเขต (commit ที่ pin ไว้) และรหัสจังหวัด/เขตของ production ไว้ใน `.cache/` ครั้งแรก แล้วสร้าง `data/*`, ทะเบียนโลโก้ (ใช้ไฟล์ที่ SHA-256 ตรงกับชีตเท่านั้น และเก็บไฟล์เดิมไว้), ตาราง noscript และ JSON-LD จากนั้นรัน `npm test` และพิมพ์ตัวเลขสรุป
3. อ่าน [data/build-report.json](data/build-report.json) (สคริปต์พิมพ์รายการ REVIEW ก่อนรัน test): ค่า `venue_qualification_status` ใหม่ที่อ่านด้วยกฎ `fallback` (ถือเป็นรอตรวจ ไม่นับ และทำให้ test ไม่ผ่านจนกว่าจะจัดเข้ากฎใน `qualification_rule()` ของ `scripts/build-data.py`; สถานะ `owner_<กฎ>_definition_accepted_*` อ่านเป็นกฎของเจ้าของโดยอัตโนมัติ) · `count_role` ใหม่ของแถวที่ผ่านนิยาม (ไม่นับและทำให้ test ไม่ผ่านจนกว่าจะจัดเข้า `COUNTED_ROLES` / `COMPONENT_ROLES` / `HELD_ROLES`) · `venue_type` ที่ผ่านนิยามแต่จัดกลุ่มด้วย keyword (เพิ่มเข้า `TYPE_GROUP`) · คำของ `coordinate_status` ที่อ่านเป็นจุดที่เลือกแล้ว · พื้นที่ย่อยที่ไม่มีโครงการแม่
4. ตรวจหน้าจอใน `npm start` ทั้งจอแคบและ desktop สองธีม เปลี่ยน cache tag `?v=` ของ entry ใน `index.html` แล้วรัน `python3 scripts/build-static.py` (import map พาทุก module ไปที่ tag ใหม่) จากนั้น commit, push `main`, รอ Pages แล้ว `npm run handoff:manifest` และ `npm run verify:live` ผล local ไม่ใช่หลักฐานแทน live URL
5. ตัวเลขในเอกสาร (ตารางข้างบน, Product Statement §2.2, `docs/BUILD_CARD.md`) เป็นภาพของ snapshot ให้แก้พร้อมกันในรอบเดียวกัน

## Assets, สิทธิ์ และการตรวจ

ใช้ LDS **0.9.7 / v0.9.7-owner.1** (`standalone-0.9.7-r1`, `color-srgb-10`, SHA-256 `d3085cbc…d432d96`) เฉพาะค่าที่หน้านี้ใช้: tokens ใน [assets/theme.css](assets/theme.css), LUT 41 ค่าของ `count` และ `density.area` ใน [js/scales.js](js/scales.js) (ใช้ครบทั้ง 41 ค่าบนแผนที่ คำอธิบายแผนที่ และกราฟ), categorical series 1–10 และ fonts ใน `assets/lds/build-kit/` (OFL) ไม่แนบคลัง LDS ทั้งชุด ไฟล์ asset บันทึกขนาดและ SHA-256 ใน [assets/manifest.json](assets/manifest.json) และทุกไฟล์ของ repository ใน `handoff/handoff-manifest.json` (สร้างด้วย `npm run handoff:manifest`) ผล hash ตรงไม่ใช่การรับรองว่าหน้าจอผ่านการตรวจหรือเป็น production

คง attribution ของ OpenFreeMap / OpenMapTiles / OpenStreetMap และ OpenGISData-Thailand รูปทรงอาคารของสถานที่มาจาก OpenStreetMap (ODbL) ผ่าน geometry bundle ของ CityMETER — README ของ bundle ระบุว่าการที่ production ใช้ได้ไม่ได้พิสูจน์สิทธิ์เผยแพร่ต่อแบบเปิดโดยลำพัง จึงคง field สิทธิ์ของแต่ละรูปทรงไว้

โลโก้สถานที่มาจากทะเบียน `10_VENUE_LOGOS` ของ Research Master: ครบ 113 ไฟล์ที่ตรวจ SHA-256 ตรงกับทะเบียนแล้ว ผูกกับ 108 สถานที่ที่นับได้ ([data/venue-logos.json](data/venue-logos.json)) สถานที่ที่ไม่มีโลโก้ในทะเบียนแสดงชื่อแทน ใช้ไฟล์ต้นฉบับไม่แก้สีหรือสัดส่วน ค้นด้วย `venue_id` เท่านั้น การรวบรวมไฟล์ไม่ใช่ใบอนุญาตเครื่องหมายการค้า สิทธิ์ยังเป็นของเจ้าของ

ทุกแถวในทะเบียนยังมี `release_status` แบบ hold (ตัวตน รูปทรง สิทธิ์ และฟิลด์ที่เหลือ) หน้านี้จึงเป็น research demo ที่เจ้าของให้เผยแพร่ ยังต้องมีกระบวนการอัปเดต สิทธิ์ข้อมูล และ field validation ก่อนยกระดับเป็น production dataset
